# GridPilot Hardware Integration Architecture

This document outlines the physical hardware loop used to demonstrate GridPilot's convex optimization capabilities in a real-world scenario.

## Overview
The hardware model consists of 5 physical charging bays simulated using dummy resistive loads. An ESP32 microcontroller acts as the telemetry and actuation layer. The ESP32 does *not* run the heavy optimization—it simply executes the schedule generated by the GridPilot CVXPY backend and reports physical current measurements back to the dashboard.

## Core Components

1. **ESP32 Dev Board (ESP-WROOM-32)**
   - **Role:** The Brain.
   - **Function:** Runs the firmware loop. Reads INA219 over I2C, decides relay states (all-on for unmanaged mode, staggered for GridPilot mode), writes LCD status, and listens for the BOOT button interrupt to flip modes. It executes whatever schedule the Render backend pushes down.

2. **12V DC Wall Adapter**
   - **Role:** Main Power Supply.
   - **Function:** Converts mains AC to a regulated 12V DC rail. This is the only mains-connected component, sealed for safety. Everything downstream runs on 12V, 5V, or 3.3V.

3. **Inline Blade Fuse (5A)**
   - **Role:** Passive Safety.
   - **Function:** Protects the circuit. If a short occurs, the element melts before wire insulation melts or the adapter is damaged. It does not limit current under normal operation (5 bays at 2.73A is well under the 5A limit).

4. **Buck Converter (12V → 5V)**
   - **Role:** Logic Power Step-Down.
   - **Function:** Steps 12V down to 5V using an efficient switching regulator. Feeds the ESP32 and the LCD's 5V rail. It is electrically isolated from the INA219 measurement branch to prevent constant logic draw from polluting the dummy EV load readings.

5. **INA219 Current Sensor**
   - **Role:** Telemetry.
   - **Function:** Sits in series with the load branch (between the 12V rail and relay bank). It has a dedicated shunt resistor and on-chip ADC. Reports clean digital current and bus voltage over I2C. This provides real-time, physical proof of load drops when relays open.

6. **16×2 I2C LCD**
   - **Role:** Local Display.
   - **Function:** Receives text commands over I2C (different address than INA219). Shows live current, active mode, and CO₂ context. It has no logic—just renders ESP32 bytes.

7. **5-Channel Relay Bank**
   - **Role:** Actuation Layer.
   - **Function:** Small electromagnetic switches. A GPIO HIGH from the ESP32 energizes the coil, closing the contact and connecting the 12V feed to a resistor bay. This provides closed-loop physical feedback.

8. **Power Resistors (22Ω 25W) ×5**
   - **Role:** Dummy EV Loads.
   - **Function:** Draw a fixed, predictable current (~0.55A per bay at 12V). This linear draw makes the scaling math perfect for the demo. They convert energy to heat (requiring standoffs and a "hot surface" warning).

9. **Bay Indicator LEDs ×5**
   - **Role:** Visual Confirmation.
   - **Function:** Wired directly across each relay's switched output to physically mirror relay state. No ESP32 logic required. They light when the bay's contact is closed.

10. **Adapter/Power-Good LED**
    - **Role:** Debug Indicator.
    - **Function:** Wired directly across the 12V rail. Indicates power is live and fuse is intact. Independent of ESP32 logic.

11. **LED Current-Limiting Resistors (220–330Ω) ×6**
    - **Role:** LED Protection.
    - **Function:** Passive elements to drop excess voltage, preventing LEDs from pulling unlimited current. 

## The Demonstration Flow (The "Wow" Factor)

The hardware operates in two distinct modes, toggled by the ESP32 BOOT button:

- **Unmanaged Mode:** 
  The ESP32 slams all 5 relays shut simultaneously. The INA219 physically measures the maximum current spike (approx. 2.75A total). The local LCD and remote dashboard show an unmanaged, dangerous power spike.
- **GridPilot Mode:** 
  The ESP32 requests the CVXPY optimized schedule from the Render backend. The backend dictates staggered charging. The ESP32 opens specific relays. The INA219 physically measures the real-time amperage drop, proving the software's ability to shed physical electrical load instantly.
